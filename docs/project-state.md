# wiiuport — project state

Factual capability inventory. Epic intent is in `docs/project-goals.md`.
Every item is `verified`, `partial`, `blocked`, or `missing`.

**Current focus.** ST-PRESENT. Framebuffer capture now works and the first two-arm null diff
was run against gameplay, and it showed that ST-NULLDIFF cannot be answered before ST-PRESENT:
what is captured is always the guest's own presented scan buffer, so a replay's output is never
seen on its own. ST-NULLDIFF stays open behind it rather than being measured again with the
same blind instrument.

## Comparison baseline

**Baseline: upstream Cemu (`cemu-project/Cemu`), used as a standalone application.**
A user today runs the Cemu AppImage, points it at a WUX, and plays at the title's own
simulation rate with community graphic packs for resolution and shading. Upstream offers
no mechanism to re-issue a frame with substituted transform state, so a 30 Hz title
presents at 30 Hz. Every item below states its difference from that baseline.

| ST-FORK | Cemu fork exists and is pinned as a submodule at a reviewable revision | verified | `SomeoneIsWorking/Cemu` forked from `cemu-project/Cemu`; `external/cemu` submodule pinned at upstream `54ffbed`. |
| ST-BUILD | Pinned fork configures and builds from a clean tree with Clang + Ninja | verified | Verified on hosted Linux from a cold checkout (run 35436011965: Clang, Ninja, full vcpkg and Cemu corpus in 32 minutes) and now locally on Fedora, producing a 299 MB `external/cemu/bin/Cemu_relwithdebinfo` with `CMAKE_CXX_COMPILER_ID=Clang` read from the configured cache. | ST-LIB | Runtime exposed to a consuming title through a narrow C++ interface | missing | No interface exists. Cemu is currently only an application entry point. |
| ST-RECORD | A frame's guest draw stream can be recorded for replay | partial | `FrameRecording` holds a frame's display lists and assembled uniform buffers by copy; `RecordingObserver` fills it from the fork's hooks. Measured on the real title through the runtime's own control channel (`GET /counters`, 12 of 12 polls answered): frames advancing to 1,642 with 487,340 display lists and 4,471,932 uniform assemblies, 0 refused incomplete, a steady ~262 lists and ~1,290 assemblies in ~306 KB per frame. The copy is required rather than cautious: 175 of 175 distinct display-list addresses recur across frames, and a test proves a recording survives overwriting its source. Exact gap: nothing replays a recording yet, and only the last complete frame is retained. |
| ST-REPLAY | A recorded frame replays with substituted transform state | partial | `LatteFrameHooks::SubmitDisplayList` feeds a recorded buffer back through `LatteCP_processCommandBuffer` on its own `DrawPassContext`, so a replay cannot leave half a draw pass in the stream the guest is mid-way through. `FrameReplayer` is armed one frame at a time over `POST /replay`. Measured on the real title: 1 replay, 288 lists submitted, 0 refused, and the runtime kept answering for 6 further polls with frames advancing 1,133 to 2,035. Exact gap: this proves the submission is accepted and survived, not that it drew the frame faithfully -- no image was compared, and no transform is substituted yet. ST-NULLDIFF is the gate for faithfulness and is still missing. |
| ST-REPLAY-GL | Interpolation under the OpenGL renderer | missing | Deliberately out of scope: the assembly site used for substitution is the Vulkan renderer's. OpenGL presents at the guest rate. |
| ST-CAMERA | The view transform is located at run time by what its values do | verified | `interp::TransformSearch` finds it by behaviour, never from a table of offsets. Measured in gameplay: 9,982 spans across 211 shaders over 4,658 frames, rejecting 991 as varying within a frame, 5,379 as never changing and 3,472 as not a rotation, leaving 140 candidates of which the top is carried by 65 unrelated shaders at differing offsets with rotation error 1.19e-07 and a mean step of 2,967.6. The same run on a title screen finds nothing and says so with its denominators, which is the negative case the search was built to report. Six tests cover each rejection class. |
| ST-NULLDIFF | Null-interpolation discriminator: replay at t=1 is byte-identical to the original frame | blocked | Blocked on ST-PRESENT, which the first real measurement is what established. `tools/null_diff.py` runs two arms against gameplay at 1920x1080: a control that captures twice with no replay between, and a replay arm with identical spacing. Measured: control 7,604 of 6,220,800 bytes differ (0.122%, largest 16), replay arm 10,741 (0.173%, largest 32). The two are the same order, so the difference is dominated by the title advancing between captures and the comparison has almost no power. The cause is structural, not a tuning problem: capture is delivered at the scan-buffer swap, which the guest owns, so replayed draws land in the current colour buffer and are overdrawn by the guest's next frame before anything is presented. Were the replay's output what is captured, re-issuing the previous frame would differ either by a whole frame of older content or by nothing; 0.05 percentage points above drift is neither. A faithful-replay claim needs the runtime to present the replay itself. Depends on ST-REPLAY and ST-PRESENT. |
| ST-PRESENT | The runtime presents a frame of its own between the guest's swaps | missing | The prerequisite ST-NULLDIFF's first measurement exposed, and the same mechanism every extra interpolated frame needs. Both HLE present packets -- `IT_HLE_COPY_COLORBUFFER_TO_SCANBUFFER` (0xF3) and `IT_HLE_TRIGGER_SCANBUFFER_SWAP` (0xF8) -- are dispatched inside `LatteCP_processCommandBuffer`, so they are reachable by synthesising a buffer for the existing `LatteFrameHooks::SubmitDisplayList` without new fork code on the hot path. Exact gap: the copy packet's nine arguments are not recorded, so `RecordingObserver` needs a callback for them before a present can be synthesised. |
| ST-SHADOW | Substituted transform storage never writes back to guest memory | missing | Depends on ST-REPLAY. |
| ST-COUNTERS | Runtime reports frames recorded/replayed, bailouts by reason, substituted slots, all with denominators | missing | Required before any interpolation claim. |
| ST-CONTROL | Opt-in control channel for input injection, frame stepping, counters, capture | partial | `lucent::http::Server`, loopback only, opened only when `WIIUPORT_CONTROL_PORT` is set. Live routes: `GET /counters`, `GET /transforms`, `POST /replay`, `POST /input`. Input injection is measured on the real title: 4,638 of 4,660 gamepad reads driven, which is what first carried a run into gameplay. Framebuffer capture is live over `POST /capture` and `GET /capture`: `FrameCapture` arms the upstream one-shot screenshot request, which hands back the presented scan buffer before the imgui overlay, and returns `std::nullopt` so no on-screen notification fires. The body is self-describing (`WIIUIMG1` magic, 16-byte header) and `tools/wiiuport/image.py` refuses a short, foreign, truncated or zero-size body by naming which. Measured on the real title: four 1920x1080 captures delivered in one run. Exact gap: no frame stepping, and capture observes only the guest's present, so it cannot show a replay's own output (ST-PRESENT). |
| ST-HEADLESS-ENV | Offscreen, silent, isolated environment for maintainer runs | verified | `tools/wiiuport/headless.py`. Live run reported `DISPLAY=:97`, its own `XDG_CONFIG_HOME`, a working X server, and clean teardown; settings name no audio device. 7 tests cover isolation, the timeout path, the exit-code path, refused missing keys, and the self-kill guard. |
| ST-HEADLESS-GAME | A maintainer run reaches gameplay in that environment | verified | A driven offscreen run reaches gameplay: 12 presses queued, 4,638 of 4,660 gamepad reads driven, 211 shaders (against 60 on the title screen) and a view transform shared by 65 unrelated shaders moving 2,967 units a frame. Two defects had to be fixed at their cause to get there: a headless session wrote no controller profile, so the VPAD HLE found no emulated gamepad and never called into one; and `SDL_hid_init`'s failure was unchecked in the Wiimote provider, so `SDL_hid_enumerate` dispatched through a null platform pointer and killed the process before a game loaded. |
