# wiiuport — project state

Factual capability inventory. Epic intent is in `docs/project-goals.md`.
Every item is `verified`, `partial`, `blocked`, or `missing`.

**Current focus.** What the objects drawn un-blended are (ST-OBJECTS): per tick about 427
whose midpoint lands on nothing in the frame between and 78 with no draw of their own two
frames back, and effects drawn without uniform blocks, which are neither blended nor counted.
The camera and every object drawn through uniform blocks interpolate continuously on the real
title: before every guest swap the runtime replays the finished frame with the view and each
object blended half way from the previous frame, presents it, puts the guest's frame back, and
lets the guest's own swap show it. Measured walking on the GPU: 715 of 722 ticks interpolated
at a title rate of 28.8 Hz (30.1 Hz with interpolation off), frame time p50 16.7 ms and p99
34.2 ms.

## Comparison baseline

**Baseline: upstream Cemu (`cemu-project/Cemu`), used as a standalone application.**
A user today runs the Cemu AppImage, points it at a WUX, and plays at the title's own
simulation rate with community graphic packs for resolution and shading. Upstream offers
no mechanism to re-issue a frame with substituted transform state, so a 30 Hz title
presents at 30 Hz. Every item below states its difference from that baseline.

| ST-REPLAY | A recorded frame replays with substituted transform state | partial | `LatteFrameHooks::SubmitDisplayList` feeds a recorded buffer back through `LatteCP_processCommandBuffer` on its own `DrawPassContext`, so a replay cannot leave half a draw pass in the stream the guest is mid-way through. `FrameReplayer` is armed one frame at a time over `POST /replay`. Measured on the real title: 1 replay, 288 lists submitted, 0 refused, and the runtime kept answering for 6 further polls with frames advancing 1,133 to 2,035. A replay now demonstrably draws: with the TCL-queue command buffers hooked (`LatteCP_itIndirectBufferDepr`, previously unobserved, which is why every earlier replay was state without geometry) one measured replay of 16 recorded buffers walked 1,408 packets, issued 36 draws and produced 64 uniform assemblies of the runtime's own, matching the 64 the recording held. The slots offered are restricted to shaders that drew in the most recent frame, so a shader whose last values outlive the frame it stopped drawing in cannot be armed. Every guest draw is counted by origin -- 926,638 from command buffers, 0 from the ring. Exact gap: a replay is armed one frame at a time over the control channel, not run every frame (ST-60), and only the view is substituted, not actor transforms.

| ST-NULLDIFF | Null-interpolation discriminator: replay at t=1 is byte-identical to the original frame | partial | The instrument is now readable and the measurement is not yet conclusive. `tools/null_diff.py`'s control -- present the same buffer again, replaying nothing -- is byte-identical over all 6,220,800 bytes, which it was not before ST-PRESENT's screen defect was fixed (11,704 bytes differed in a 45x135 box that turned out to be a GamePad item icon). Exact gap: that result cannot yet distinguish a faithful replay from one that drew nothing, because the replay redraws the frame that is already in the colour buffer -- both produce the same image. The counters say so plainly: a run that replayed 470 lists reported 0 display lists and 0 uniform assemblies coming back from the runtime's own submissions, which is either a replay whose draws reused unchanged uniforms or a replay that never drew. The discriminator now exists and runs: `tools/interpolated_frame.py` substitutes a blended view into the replay and requires the image to change. Its first run answered the open question -- the replay was issuing **zero** draws over 532 packets, so "identical" meant "drew nothing" -- and the cause was an unhooked command-buffer path, now fixed. Both arms now answer: the control is byte-identical over all 6,220,800 bytes, and the substituted replay **differs** -- 1,823,023 bytes (29.305%), largest 215, mean 1.0315, bounding box the whole 1920x1080 frame, 1,080 rows touched. | ST-PRESENT | The runtime presents a frame of its own between the guest's swaps | verified | `LatteFrameHooks::SubmitPresent` assembles the guest's own two packets -- `IT_HLE_COPY_COLORBUFFER_TO_SCANBUFFER` (0xF3) and `IT_HLE_TRIGGER_SCANBUFFER_SWAP` (0xF8) -- in big-endian and feeds them through the same command processor, so the encoding stays with the code that owns it and the runtime supplies only arguments it observed. A nested present is refused, and `InRuntimePresent()` keeps the runtime's own swap from publishing a frame end the guest never reached. Which screen is presented is the whole of the difficulty: a title copies to a scan buffer twice per frame, once for the TV and once for the GamePad -- measured at 922 presents across 460 frames of Wind Waker HD -- so keeping the last one presented the GamePad's buffer into the window the user watches, and a control that should have been byte-identical came back with a GamePad item icon drawn across it. The target bits are now decoded at the hook boundary, where Latte owns them, and `FramePresenter` keeps the TV's arguments; a GamePad-only observation is refused by name rather than presented to the wrong screen. `GET /counters` reports presents observed split by screen. |
| ST-60 | The camera moves at the display's rate, blended between the title's own frames | partial | `interp::ContinuousInterpolator` runs at `OnFrameComplete`, the fork's hook between a finished guest frame and its swap: replay the frame with the view blended at t=0.5 between the previous frame's and this one's (`Transform3x4::blendView`, a pose blend through the rigid inverse, so the camera moves and the world does not), present it, then copy the guest's frame back to the scan buffer (`SubmitScanBufferCopy`) for the guest's own swap. `interp::ViewTracker` follows the view frame to frame and reseeds from the search every 8 frames. The display spaces the two presents, not the CPU: `ShellHost` selects FIFO when interpolation is on. A CPU wait to half a tick was tried first and measured cutting the title from 30.10 Hz to 20 Hz, because a wait inside the frame delays the next one. Measured on the GPU with `tools/continuous_run.py`, 25 s of swimming: 717 of 725 ticks interpolated, 0 restores refused, the title at 28.9 Hz against 30.1 Hz with interpolation off; per interpolated tick 3.29 ms replaying, 1.21 ms presenting, 2.85 ms restoring. The run fails when no tick was interpolated. `interp::CutDetector` withholds a blend across a cut, by turn (over 45 degrees a tick) or by step (over 8x the recent median); it first locked its median at the camera's resting rounding and called 745 of 753 walking ticks cuts, fixed by remembering every step, cuts included, and ignoring steps within 16 ulps of the camera's distance from the origin. Every tick not interpolated is counted by reason (`GET /interpolation`). A still view blends to itself bit for bit (`Transform3x4::blend`/`blendView` return an endpoint the two share; through two rigid inverses and a slerp 60 of 64 held views came back with other bits). Frame times are measured where the renderer returns from each present, the title's and the runtime's alike (`frame::PresentPacing`, fed by the fork's `OnDisplayed`, restarted by `POST /pacing`): walking, 722 title frames and 716 in-between frames in 25.1 s (57.3 a second at a title rate of 28.8 Hz), frame time p50 16.7 ms, p95 28.8 ms, p99 34.2 ms, longest 57.1 ms over 1,437 intervals. Exact gaps: the two halves of a tick are handed over unevenly, 23.0 ms from the title's frame to the in-between one and 11.5 ms back, because the in-between frame can only be drawn once the title's frame is finished; whether the FIFO queue evens them out at scan-out is not measured, since the renderer cannot see scan-out; the title runs at 28.8 Hz against 30.1 Hz with interpolation off, so the display gets 57 frames a second, not 60. |
| ST-OBJECTS | Actors, objects, and effects move at the display's rate, each blended by its own identity | partial | The title double-buffers its uniform blocks: of 1,319 recurring block addresses on a 16-frame snapshot, 1,217 recur only at one frame parity, so a draw's identity (shader, sourced block addresses, occurrence among identical draws: `interp::AssemblyKey`) recurs two frames apart, and 92.8% of draws recur by it at N-2 against 29% at N-1. `interp::ObjectPlanner` therefore blends each draw of frame N with its own draw in N-2 at s = (1 + t) / 2 = 0.75, which is t = 0.5 of N-1..N for an object moving steadily, and only after checking that the midpoint lands on the object's partner draw in N-1 within a quarter of its step (a different object, or the same one standing at either end, lands at a half). Partners are learned as block pairs and derived on later frames; a search, exact and indexed by each shader's widest-spread value, runs otherwise, and one that fails waits 8 frames. A blend is drawn only if it lies strictly between the object's two neighbours, nearer each of N-1 and N than they are to each other, checked on the values drawn; one that does not is counted as outside and drawn as the title drew it. Only numbers are blended; integers stored in floats take the later frame's value and are counted. The replay writes each planned blend by draw order and stops for the frame, counted, at the first draw out of step with the recording. Planning runs on its own thread (`interp::ObjectBlend`) as the guest draws: on the rendering thread it was measured cutting the title to 25.5 Hz, at frame end to 24 Hz. A held-still world, the camera included, replays byte-identical to the title's frame (`aHeldStillWorldReplaysByteIdenticalToTheTitlesFrame`, over 16 camera angles, 12 of which fail without the exact-endpoint blend). Measured walking with `tools/continuous_run.py`, 715 interpolated ticks: per tick 1,847 objects blended, 700 held still, 78 with no draw of theirs at N-2, 427 whose midpoint landed on nothing in N-1 and 0.04 outside their neighbours, all but the blended drawn as the title drew them and counted at `GET /interpolation`; 0 replays out of step; title rate 28.8 Hz. Exact gaps: no capture of an in-between frame has been compared by code with its neighbours' images, only the values drawn; what the 427 unverified and 78 unmatched objects a tick are is not known; effects drawn without uniform blocks (particles as vertex data) are not blended at all and not counted. |
| ST-SHADOW | A runtime replay never changes guest-visible state | partial | The blend is written only into the runtime's own assembled uniform buffers, never guest memory. A replay re-issues packets whose effects the guest has already consumed, so the fork withholds each class while a runtime buffer is walked and counts it: presentation, synchronisation (semaphores, memory waits), guest memory writes (fences, timestamps, stream-out sizes), occlusion queries, and render-target readbacks. The runtime's own present is the one presentation allowed. Measured in the continuous run: 5,740 guest presentation packets withheld from replays, and the title ran on at its own rate with no hang. Exact gap: no test asserts guest memory is byte-identical across a replay. |

| ST-PAD | A gamepad is mapped automatically and can be swapped mid-game | verified | `shell/ControllerAutoMap` attaches the first SDL gamepad to player 1's emulated GamePad and applies 25 bindings laid out by position, so the button under the thumb is the one the Wii U had there; the table is checked against the working profile it was derived from.
